# 05 SDD → TRAE → Xcode 协作工作流 v0.1

## 1. 角色
- **用户**：使用iPhone观察CamCard、执行Xcode/Simulator与必要真机测试、把真实执行反馈给ChatGPT；决定最终规格/架构变更。
- **ChatGPT**：读课程文件、管理规格与可追踪测试、编写阶段性TRAE Prompt并归档、审核TRAE回复、记录进度及风险。
- **TRAE**：只在**批准的规格与单次任务边界内**规划/编辑代码、编写单元测试与提出差异；不能未经许可改模型接口、越范围加功能、声称实际通过未执行测试。
- **Xcode**：iOS App 构建、模拟器运行、测试、签名和调试的权威执行环境；TRAE仅编辑源码不能替代Xcode实际构建结果。

## 2. 完整闭环（每一功能单元都执行）
`观察结果 → Specification条目 → 设计/接口审阅 → 小步实现 → 本地构建/单元测试 → 黑盒对照 → 差异分析 → 定点修复 → 全量回归 → 冻结成果`。

**输入必须包含**：需求ID、可修改文件范围、已有接口、禁止修改项、边界样例、验收用例；**输出必须包含**：变更文件列表、实现说明、未解决问题、测试证据；缺真实测试不得写PASS。

## 3. 质量门槛
| Gate | 通过条件 | 不通过处理 |
|---|---|---|
| G0 观察基线 | 区分课程要求/观察实测/技术决策/未验证 | 不允许AI猜测未见界面 |
| G1 规格基线 | 每条功能具ID、验收条目、清晰边界 | 不写代码，先补规格 |
| G2 架构基线 | 数据模型/存储/服务边界确认、变更影响范围明确 | 不批量创建模块 |
| G3 每次增量 | 改动小、代码可构建、相关单测运行 | 退回定位修复，保留失败记录 |
| G4 质量回归 | 已通过测试无回退，差异有解决/记录 | 暂停下一阶段 |
| G5 最终交付 | 20条T场景均有结果、OCR Ground Truth统计、工程可运行、全部Prompt与文档齐 | 不冒称100%完成 |

## 4. 六周分工（课程原次序）
- **W1** 黑盒观察、页面/状态清单、逻辑Schema、30～50张测试集与Ground Truth准备、spec.md、Reference Test Suite。当前W1刚生成基线草案，数据集和少量观察缺口待补。
- **W2** 架构、导航、数据模型、Repository、名片夹/详情/空态、Mock Data、首批单元测试。
- **W3** 相机、相册导入、区域检测、裁剪/校正、OCR、OCR Raw Result和自动测试。
- **W4** 字段解析与置信/异常、人工修正与保存（概率性AI转可靠数据）。
- **W5** 搜索、Group/Tag、Note、编辑删除、持久化、联系人/VCF导出、UI Golden Test。
- **W6** 所有T案例、正式30～50张评估、OCR/字段错误分析、回归、边界修复、SDD和AI档案、最终演示。

## 5. TRAE提示词归档纪律
1. 每条唯一 `P001`、`P002` ...；每条独立完整 `.md` 原文，发送前标记 `DRAFT`。
2. 用户**实际发送**后，保存确切发送原文、时间、目标、关联R/T、TRAE回复与变更列表、是否经过人工审查、是否通过Xcode测试。
3. AI回答失败或返工的提示词**不能删除**；用新Prompt ID记录修复，标注 Bug/回归关系。
4. 未发送的草稿不计入“实际使用的所有提示词”；不能提前宣称发送或执行。
5. 禁止一步生成整个App，禁止模型默认“自行完善”课程之外功能。
