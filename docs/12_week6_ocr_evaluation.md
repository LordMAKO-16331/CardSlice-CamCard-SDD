# Week 6 OCR 与字段解析评估

## 1. 评估目标

课程要求用 30～50 张名片及人工核对的 Ground Truth 评估识别质量。本项目保留四个数据阶段，以定位错误发生在哪一步。

| 阶段 | 数据及用途 |
| --- | --- |
| OCR 原文 | Apple Vision 读取的文字，用于核对漏读、误读及字符混淆 |
| 自动解析 | 从 OCR 结果抽取并分类的字段，本轮定量评分对象 |
| 人工核验与校正 | 用户对照名片与 OCR 原文，补齐或修正字段 |
| 最终保存 | 用户确认后持久化的联系人，同时保留 OCR 原文和初始解析供追溯 |

本轮以字段完全匹配率和字段值召回率衡量自动解析结果。OCR 原文用于诊断上游错误，本轮未计算 OCR 逐字符准确率。[规格](spec.md) · [参考测试](03_reference_tests.md)

## 2. 测试环境

正式批次在 iPhone 17 Simulator / iOS 27.0 采集。调用链为 `CardImagePreparationService` → `CardTextRecognitionService`（Apple Vision OCR）→ `CardContactFieldParser`。35 张有文字的结果记录了简体中文（`zh-Hans`）和英文（`en-US`）识别配置。

批量输入标记为 `prepared_without_perspective_correction`，即使用项目预处理后的图片，未经过人工调整和透视裁剪。用户已验证的真机拍摄及扫描流程属于另一项功能证据。[正式采集 JSON](../evaluation/4373F066-3A8B-483B-BAED-7E227482407E.json) · [采集说明](../evaluation/README.md)

- **正式集 F01～F36，共 36 张。** 8 张中文、8 张英文、8 张中英双语、6 张竖版或特殊布局、6 张低清晰度或复杂背景。覆盖模糊、低对比度、布局变化、多电话、多邮箱、传真和字段缺失等情形。受扰动样本的清晰原版保留作复现材料，未重复计分。[数据集说明](../evaluation/formal/README.md) · [正式真值](../evaluation/formal/ground_truth.json)

两组共 40 张，分别呈现结果。这是合成名片测试集，样本构成、字体、布局与扰动分布限制了向真实商业名片场景的推广。

## 4. 评估方法

Ground Truth 是人工核对或依据合成卡面生成并核验的字段值，独立于自动识别输出。按样本 ID 对齐同一字段，并使用现有计分器的归一化规则。

| 字段 | 归一化规则 |
| --- | --- |
| 通用 | Unicode NFC，去除首尾空白 |
| 电话（各类型独立） | 将指定的全角数字与电话标点转为半角，去掉空白、括号、点和连字符或长短破折号，保留数字、前导零及国际区号前的加号 |
| 邮箱 | 域名转小写，保留用户名大小写 |
| 网站 | 裸域名按 HTTPS 比较，协议和主机名转小写，无后缀时补根路径斜杠，保留显式 HTTP、路径及查询等内容 |
| 其余文本 | 连续空白折叠为单个空格并做大小写折叠，仍保留标点、全半角差异及有无分隔空格的差异 |

**字段准确率**以有非空真值且该阶段纳入评价的字段为分母。归一化后整个字段的值及出现次数完全相同才得分。**字段值召回率**以这些字段中的预期值总数为分母，逐值统计匹配。多电话和多邮箱以多重集合比较，顺序不影响结果，重复值按出现次数比较。

预期值未匹配记为缺失，预测值没有对应真值记为多余。错误替换可同时产生缺失与多余。已确认为空却被填充的字段另计，未核对的真值和未采集阶段不进入对应分母。计分器的跨字段提示依赖同一归一化值在其他字段中出现，语义归错但字符也被误读时，仍需结合原文诊断。[计分器源码](../evaluation/evaluate.py)

## 7. 人工校正与数据可靠性

用户可以在识别结果页查看 OCR 原文和自动解析字段，对照名片检查漏项或错项，通过人工校正表单修改后主动确认保存。原文和初始解析保留，最终联系人字段采用确认值。例如 F01 可从卡面补入姓名及公司并核对邮箱，F35 可修正号码及对应类型。人工修改与保存已有用户功能验证。正式 JSON 的 `corrected_fields` 均为 `null`，当前没有校正后的定量准确率。[规格](spec.md) · [正式采集 JSON](../evaluation/4373F066-3A8B-483B-BAED-7E227482407E.json)

## 9. AI 能力边界

- Vision 的识别受字形、图片质量和布局影响。解析和计分按确定性规则处理输入，因此同一误读可能被稳定地保留到下游。F01 的邮箱即使格式有效，邮箱里的字符仍可能有误。
- 从图片读出文字和判断文字的角色是两个问题。F17 读出了公司全称但公司字段为空。正式集手机和办公电话分别为 32/36 和 21/24，姓名和公司分别为 3/36 和 0/36。号码可依靠格式和标签，姓名、公司和职位通常还依赖布局与语义，且样本数不同，尤其传真仅有 9 个有效字段。
- F35 说明标签和号码一起误读时，格式规则也会退化。F31 则说明管线可能完全没有文字输出。保留这些结果能让分母反映全部测试输入，也能区分识别失败与仅在成功读出文字后的抽取质量。
- 用户核验能发现格式检查无法识别的错误，例如正确格式中的错误数字或合法域名中的误读字符。保存前的人工确认决定最终数据质量，自动分数只描述用户介入前的结果。

## 10. 总结与局限性

项目已完成 40 张合成名片的自动识别评估，其中 36 张具有可追溯的正式采集和评分明细，4 张先导的汇总取自用户报告。正式集字段准确率 51.5267%，字段值召回率 52.3985%，主要薄弱环节为姓名和公司。人工校正已实现，校正后准确率及参考 CamCard 的定量对照仍未统计。结果适用于本次合成数据和预处理输入，不能直接外推到真实商业名片或真机拍摄全流程。业务代码已冻结，本报告作为课程交付证据。
