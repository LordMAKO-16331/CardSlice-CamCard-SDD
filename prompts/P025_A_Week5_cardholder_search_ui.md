## 四、任务一：明确普通列表与搜索模式

实现两个清晰的 UI 状态。

### 普通列表状态

未激活搜索时：

- 正常显示全部已保存名片。
- 如果选择了标签，只显示该标签下的名片。
- 保持原有列表、计数与导航。
- 不出现无意义的空搜索提示。

### 搜索激活状态

用户点击搜索框后：

- 搜索框获得焦点。
- 输入非空关键词时显示匹配结果。
- 没有输入关键词或仅输入空白字符时，不显示名片搜索结果。
- 可以显示简短的「请输入搜索关键词」提示。
- 提供清晰的退出或取消搜索方式。
- 退出搜索后恢复原本的名片列表。
- 清空关键词不应修改数据库。
- 当前标签筛选条件在进入、退出搜索后保持正确。

必须区分「搜索未激活」与「搜索已激活但关键词为空」，不能简单通过空字符串决定所有页面状态。

## 五、任务二：关键词高亮

搜索结果应展示命中的信息，并对能够准确定位的关键词进行高亮。

至少支持：

- 姓名
- 公司
- 职位
- 电话
- 邮箱
- 备注

要求：

1. 对姓名、公司、职位等当前显示的字段，高亮匹配文字。
2. 英文关键词匹配不区分大小写。
3. 中文关键词正常高亮。
4. 高亮不能改变原始字段内容。
5. 不得通过修改数据库字符串实现高亮。
6. 关键词清空后恢复普通文本。
7. 不能因为高亮导致文字截断、换行异常或点击区域失效。

电话号码原有搜索支持忽略空格、横线等分隔符。

高亮必须考虑原始号码与规范化查询的差异。若无法安全映射到原始字符位置，应明确展示完整的匹配号码，而不是错误地高亮无关字符。

## 六、任务三：展示命中的字段

对于原本不在名片列表摘要中显示的字段，增加简洁的匹配信息。

例如：

搜索邮箱 `alex@example.com`：

名片原有姓名及公司信息\
匹配邮箱：[alex@example.com](mailto:alex@example.com)

搜索备注 `Follow up`：

名片原有姓名及公司信息\
匹配备注：Follow up next week

搜索电话号码：

名片原有姓名及公司信息\
匹配电话：实际保存的完整号码

要求：

1. 展示已保存的真实字段，不使用 Mock 或猜测值。
2. 对命中姓名、公司、职位的情况，可直接在现有摘要字段中高亮。
3. 对电话、邮箱、备注等隐藏字段，至少显示一项准确的命中摘要。
4. 不需要把一张名片的所有字段展开。
5. 同一名片命中多个字段时只出现一张结果卡片。
6. 列表点击后仍进入正确名片详情。
7. 较长的备注可截取相关片段，但不得改变原文。
8. 空备注、空电话、空邮箱安全处理。
9. 数据更新后搜索结果和匹配摘要及时刷新。
10. 不泄漏其他名片的数据。

尽量复用 CardSearchService 的匹配逻辑，避免筛选结果和高亮展示相互矛盾。

## 七、保持标签筛选兼容

原有逻辑必须保留：

→ 关键词搜索\

- 删除标签或名片后 UI 正确刷新。
- 普通列表总数与搜索结果数不能混淆。
