## 四、审查任务 A：功能完整性

按照课程功能一至功能十逐项检查。

每项说明：

- 对应需求。
- 已有实现文件。
- 现有测试证据。
- 是否存在功能缺口。
- 是否仅缺少人工验证。
- 后续建议。

特别检查：

1. 电话、邮箱、Website 在详情页是否能调用对应系统操作。
2. VCF 字段类型与多号码导出。
3. 取消编辑、取消识别、取消拍照时的数据状态。
4. OCR 无结果、图片无名片边界等异常路径。
5. App 重启后的图片、备注、标签与修正字段保存。
6. 空数据、重复字段、多号码、多邮箱处理。
7. 已保存记录与 OCR 草稿之间的数据隔离。

严禁仅因某个按钮存在就判断整个功能通过。

## 五、审查任务 B：UI 与交互流程

检查实际 SwiftUI 页面及导航。

重点：

### 名片夹

- 空状态是否正确。
- 搜索与标签筛选是否协调。
- 名片列表是否有清楚的信息层级。
- 扫描入口是否易于发现。

### 扫描流程

检查能否自然完成：

选择拍摄或相册\
→ 图片预览\
→ 名片边界检测与调整\
→ 确认裁剪\
→ OCR\
→ 人工确认\
→ 保存\
→ 返回名片夹

检查是否存在：

- 多个技术功能全部堆在一个长页面。
- 必须滚动寻找下一步按钮。
- 返回、取消、重拍与重新选择图片语义不清楚。
- 加载、失败、重试状态缺失。
- 开发测试按钮混入正常使用流程。

### 名片详情

- 姓名、公司、职位区分。
- 电话、邮箱、网站及地址展示。
- 备注入口。
- 标签入口。
- 图片展示。
- 编辑、删除、导出入口。

### 名片编辑与人工校正

- 动态字段增删操作。
- 保存与取消。
- 键盘与滚动问题。
- 两种编辑入口的一致性。
- OCR 识别原值与人工修正值的区分。

### 全局一致性

- 简体中文文案。
- 按钮大小与操作可达性。
- 导航与返回方式。
- 弹窗、错误提示、空状态。
- DEBUG 工具隔离。

## 九、审查规则

1. 静态代码可以证明的内容标记「代码已确认」。
2. 只有用户报告过的实际验证才可标记「用户已验证」。
3. 无法证明的内容标记「待验证」。
4. 真正缺少的内容标记「缺失」。
5. 不得因为没有测试截图就认定代码功能不存在。
6. 不得因为现有代码有相关方法就认定完整业务流程通过。
7. 不得把单纯的视觉偏好误写成课程硬性要求。
8. 不得建议课程范围外的大型功能。

所有问题尽量给出准确文件名与方法、组件位置。

## 十、执行限制

只允许必要的源码、测试和文档读取，以及两份 Markdown 归档。

- 执行 xcodebuild。
