# P016-F01 — 姓名候选与解析结果一致性修复

## 一、问题背景

当前 CamCard SDD 项目已实现 P016 字段解析、P017 人工校正及 P018 正式名片保存。

用户实际测试发现：

- OCR 能识别名片文字。
- 姓名字段有时显示“未识别”。
- 但下方的候选或推断信息中已经出现正确姓名。
- 人工校正和正式保存功能正常。
- P018-F01 修复后，全部 Xcode 回归测试通过。

本轮只排查和修复姓名解析结果不一致的问题。

- CardFieldCorrectionDraft.swift

2. 姓名候选如何排序和判定。
3. 解析结果中的 name 如何赋值。
4. UI 为何显示“未识别”。
5. 人工校正页面使用哪个数据字段。

## 四、修复要求

如果发现是数据传递或 UI 映射错误，进行最小范围修复。

如果发现是候选判断过于保守，应检查现有判断规则，采用可解释的方式优化。

要求：

1. 高可信度、无明显冲突的姓名候选可以正确进入姓名字段。
2. 多个有歧义的候选不能被强制认定为姓名。
3. 不得将公司名误当作姓名。
4. 不得针对4张测试名片硬编码姓名。
5. 原始 OCR 文本和全部候选信息必须保留。
6. 不能为了填满姓名字段而编造内容。
7. 人工校正流程仍须允许用户修改姓名。
8. 不得修改正常工作的 SwiftData 保存逻辑。

1. 正确且唯一的姓名候选能够成为解析姓名。
2. 中文与英文姓名。
3. 公司名位于姓名前面。
4. 多个姓名候选存在歧义。
5. 无可靠姓名时保持未识别。
6. 修复后不会破坏电话、邮箱和公司解析。
