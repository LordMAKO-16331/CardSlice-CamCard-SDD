## 五、T01：首次启动

要求：

首次启动后，正确显示空名片夹。

需要明确：

1. 如何在不破坏现有名片数据的前提下测试空状态。
2. 是否可以使用独立的测试模拟器。
3. 是否需要隔离测试数据。
4. 空状态需要显示哪些入口。
5. 保存第一张名片后如何更新列表。

不得要求用户清除当前模拟器已有的正式测试记录。

如果现有环境无法安全制造首次启动状态，标记 NOT_RUN 并说明所需条件。

## 六、T02：进入扫描

验证：

1. 从名片夹找到扫描入口。
2. 点击后进入扫描来源页面。
3. 拍摄与相册入口均可见。
4. 返回或关闭操作正常。
5. 没有意外创建名片。

对照当前已实现的分阶段扫描流程和课程原始要求。

## 七、T03：相机权限

分别准备：

1. 首次允许权限。
2. 拒绝权限。
3. 拒绝后重新进入。
4. 系统限制或设备不可用。

明确区分：

- 设备实际权限测试。
- 模拟器不可用状态。
- 代码中已有的权限决策单元测试。

不能用模拟器的相机界面代替真实设备权限验收。

如果当前没有可用真机测试条件，保持 BLOCKED 或 NOT_RUN，并记录原因。

不得要求用户为了测试直接升级真实 iPhone。

## 八、T04：真实相机拍摄

准备以下验证场景：

1. 拍摄标准名片。
2. 拍摄后查看预览。
3. 确认进入裁剪。
4. 重拍。
5. 取消。
6. 退出后检查数据库没有意外记录。
7. 拍摄后进入后续识别流程。

真实拍照需要支持相机的设备。

模拟器不能拍照不等于该业务代码失败，也不能算 PASS。

## 九、T05：相册导入

使用现有虚构测试名片。

验证：

1. 打开系统图片选择器。
2. 选择单张名片。
3. 自动进入裁剪界面。
4. 图片显示正确。
5. 取消选择。
6. 重新选择其他图片。
7. 返回上一步。
8. 旧图片状态不会残留。
9. 不会因为取消而产生持久化记录。

说明 PhotosPicker 与传统整库照片权限申请的行为差异。

不得虚构用户未实际观察到的权限弹窗。

## 十、T06：名片边界与裁剪

至少准备：

1. 正常矩形名片。
2. 倾斜名片。
3. 多候选矩形。
4. 无明显矩形的图片。
5. 手动四角调整。
6. 恢复候选。
7. 确认裁剪。
8. 透视校正结果。
9. 返回并重新裁剪。
10. 错误或无效四边形的处理。

必须检查裁剪前后的实际图片，不得仅因算法单元测试通过而直接判定 T06 成功。

## 十一、正式验收记录格式

每项测试采用统一格式：

- Test ID。
- 对应需求。
- 前置条件。
- 操作步骤。
- 预期结果。
- 实际结果。
- 执行设备。
- 执行日期。
- 证据文件。
- PASS / FAIL / BLOCKED / NOT_RUN。
- 缺陷编号及复测结果。

区分以下状态：

PASS：实际执行且满足预期。\
FAIL：实际执行后发现不符合要求。\
BLOCKED：由于明确环境或功能条件无法执行。\
NOT_RUN：尚未执行。

初始 T01～T20 全部保持 NOT_RUN。

准备度与实际执行结果可以分列记录，避免混淆。

## 十二、后续验收规则

1. 用户手动执行测试。
2. 用户提供实际结果后，才允许更新验收状态。
3. 不能修改已有 PASS 记录以掩盖回归。
4. FAIL 必须保留原始问题及修复后复测记录。
5. 不能删除、重置或覆盖已有名片数据库。
6. 图片证据只引用实际存在的文件。
7. 未归档的历史截图不能编造路径。
8. 不为了验收临时改变课程业务规则。

本轮只准备验收，不执行测试。
