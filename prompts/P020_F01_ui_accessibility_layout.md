# P020-F01 — UI 操作遮挡与流程堆叠定点修复

## 一、任务背景

CamCard SDD iOS 课程项目目前已完成 P020 名片删除功能。

用户在 iPhone 17 / iOS 27.0 模拟器中确认：

- 删除功能本身能够正常执行。
- 全部现有自动化回归测试通过。

但发现严重 UI 可用性问题：

1. 在名片管理界面向下滑动时，删除按钮短暂出现；松开后，按钮又被包含「保留测试名片」的区域遮挡，无法稳定操作。
2. 图片预览界面堆叠了大量功能，包括矩形检测、候选选择、透视矫正、恢复预处理图片、OCR、字段解析和人工校正。
3. 操作越多，页面越长，部分重要信息和按钮难以找到。
4. 顶部关闭按钮、标题和说明文字存在拥挤现象。

本轮只修复 UI 可达性，不进行正式 CamCard UI Golden Test，不重新设计整个 App。

- CardHolderView\.swift

- ScrollView、List、Form 的嵌套关系。
- 固定高度、overlay、offset 和底部悬浮控件。
- safeArea 与工具栏布局。
- Sheet 内部滚动与底部控件的关系。
- DEBUG 测试入口是否遮挡正式业务操作。

## 五、修复任务 A：删除按钮始终可访问

要求：

1. 检查已保存名片详情页中的删除入口。
2. 检查「保留测试名片」或其他 DEBUG 控件是否覆盖正式业务按钮。
3. 确保删除入口能通过正常滚动稳定到达。
4. 松开手指后，按钮不能被固定栏、其他控件或屏幕边缘遮挡。
5. 保证点击区域足够明确，不会误触其他操作。
6. 保留删除确认对话框。
7. 保留取消删除、确认删除和删除失败的现有行为。
8. 不允许通过隐藏删除按钮、删除 DEBUG 功能或取消确认流程来规避问题。
9. 不得改变 CardRepository 删除逻辑。

如需要调整 DEBUG 按钮位置，可以将其归入独立的开发工具区域，但保留原有功能。

## 六、修复任务 B：图片处理界面减少堆叠

当前一个页面承载了大量开发操作。

采用最小范围的分区或折叠式组织，让用户能够明确找到不同阶段的功能。

建议组织为：

### 图片处理

- 预处理图片及尺寸。
- 检测名片边界。
- 选择矩形候选。
- 应用透视矫正。
- 恢复预处理图片。

### 文字识别

- 执行 OCR。
- 查看 OCR 原始文字及识别结果。

### 字段处理

- 执行字段解析。
- 查看结构化字段。
- 打开人工校正。
- 查看确认结果。
- 正式保存名片（如当前页面提供该入口）。

要求：

1. 可以使用 DisclosureGroup 等系统组件组织已有功能。
2. 不要求所有处理结果始终同时展开。
3. 用户必须可以重新展开查看此前的结果。
4. 切换 UI 分区不得清空有效图像、OCR、解析或人工确认数据。
5. 不得因为折叠分区而重新执行 OCR 或图像处理。
6. 保存入口仍须清晰可见和可访问。
7. 页面可正常滚动到底部。
8. 不使用固定 offset 或大量硬编码空白来掩盖遮挡。
9. 保留现有功能，不删除任何处理步骤。
10. 保留 [DECISION/TEMP] 标记。

本轮只解决开发界面的组织与可达性，不要求完全复刻 CamCard 页面样式。

## 七、修复任务 C：顶部与人工校正页面

1. 顶部关闭按钮与标题不得遮挡内容。
2. 说明文字过长时应正常换行或放入可滚动内容。
3. 不能出现顶部内容绘制到系统状态栏下方而无法阅读的情况。
4. 人工校正表单应能够滚动。
5. 键盘弹出时，输入字段和确认操作不能被永久遮挡。
6. 取消与确认行为保持不变。
7. 不修改字段校验及保存数据逻辑。

## 八、回归保护

- 相册图片导入。

- 矩形检测与候选选择。
- 透视矫正。

- DEBUG 测试名片入口。

不得为修复 UI 而改变这些功能的数据流程。
