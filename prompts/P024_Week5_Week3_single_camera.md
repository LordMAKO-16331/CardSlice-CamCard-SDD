## 四、功能要求

### 1. Single 拍摄入口

在现有扫描界面增加可见的「拍摄名片」入口。

要求：

- 在支持相机的真实 iPhone 上调用原生相机。
- 只拍摄一张名片。
- 不实现 Batch、Multiple、QR 或 High Accuracy。
- 不开发自定义实时取景界面。
- 继续保留相册导入。
- 不遮挡现有按钮。

优先使用系统原生相机组件，避免不必要的 AVFoundation 拍摄架构。

### 2. 相机权限

正确处理：

- 首次请求权限。
- 已授权。
- 用户拒绝。
- 系统限制。
- 设备没有可用相机。

要求：

1. 不得在用户拒绝权限后反复请求。
2. 权限拒绝时给出明确提示。
3. 可以提示用户到系统设置修改权限。
4. 不能因缺少相机设备而崩溃。
5. 不得将模拟器相机不可用误判为程序错误。
6. 如需 NSCameraUsageDescription，仅在实际必要的 Info.plist 或工程配置位置做最小修改。

如必须修改工程配置，仅允许增加必要的相机权限说明，不得改变其他 Build Settings。

### 3. 拍摄与返回

要求：

1. 用户点击拍摄后进入系统相机。
2. 用户取消时安全返回扫描页面。
3. 取消不得生成空白名片记录。
4. 拍摄成功后取得原始图片。
5. 将图片送入现有图像处理流程。
6. 保留原图和处理图的现有数据语义。
7. 失败时提供错误提示。
8. 不允许使用固定 Mock 图片伪装相机拍摄成功。

### 4. 接入原有识别管线

拍摄后的流程应为：

相机拍照\
→ 图片预览\
→ 边界检测与校正\
→ OCR\
→ 字段解析\
→ 人工确认\
→ 保存

要求：

- 复用相册导入使用的服务及现有状态流转。
- 不复制另一套 OCR、Parser 或保存逻辑。
- 正确处理图片方向。
- 不因为相机拍摄而降低原有图像分辨率要求。
- 保存后保持现有 SwiftData 持久化能力。
- 不影响已有的相册导入功能。

### 5. 重拍与取消

要求：

1. 拍摄后允许重新拍摄。
2. 重拍时废弃当前尚未保存的拍摄结果。
3. 取消当前流程不得覆盖已有名片。
4. 不得把上一次拍摄结果错误带入下一次会话。
5. 失败后仍可返回相册导入或重新拍摄。
