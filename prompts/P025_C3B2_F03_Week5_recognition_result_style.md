# P025-C3B2-F03 — Week 5：识别结果与人工校正页面视觉一致性修复

## 一、问题背景

CamCard SDD iOS 项目处于 Week 5 UI Golden Test 阶段。

P025-C3B2-F02 已完成扫描按钮层级调整。

用户实际截图发现：

P1「识别结果」与 P2「人工校正」界面风格明显不一致。

P1：

- 纯白背景。
- 字段直接纵向排列。
- 多个电话、邮箱之间缺乏清晰分组。
- 整体更像文本报告。

P2：

- 浅灰背景。
- 白色圆角卡片。
- 清楚的分组标题与分隔线。
- 信息层级较合理。

另外，P1 的「查看识别原文」在截图中接近固定底部操作栏，需要检查是否存在遮挡。

本轮目标：统一两张页面的视觉规范，同时保留只读与编辑的功能差异。

## 四、识别结果页面布局调整

参考现有 CardFieldCorrectionView 的视觉风格。

要求：

1. 识别结果页与人工校正页使用一致的背景风格。
2. 使用白色圆角卡片组织信息。
3. 姓名作为主要标题。
4. 公司、职位具有清晰的字段标签。
5. 电话号码集中到联系方式区域。
6. 多电话号码完整展示，并保留实际类型。
7. 多邮箱完整展示。
8. 网站、地址使用清晰的字段标签。
9. 合理使用分组标题及分隔线。
10. 字段间距保持一致。
11. 长文字可以正常换行。
12. 不显示虚假的联系人字段。
13. 空字段可使用「未识别」作为 UI 提示，但不得写入数据。
14. 不因改造布局而删除 OCR 结果中的任何有效字段。

识别结果页保持只读，不允许直接修改数据。

用户仍通过「修改识别信息」进入人工校正页面。

## 五、底部操作区域

保留：

- 确认无误，保存名片。
- 修改识别信息。
- 返回裁剪。

要求：

1. 主操作与次要操作样式保持现状。
2. 固定底部操作区域不能遮挡正文。
3. 「查看识别原文」必须完整可见且可点击。
4. 页面内容较长时可以滚动至最后一项。
5. 底部内容避让应考虑安全区域。
6. 不要使用大量固定空白填充来掩盖遮挡。
7. 姓名为空时继续禁止保存并保留原有提示。

优先使用 SwiftUI 原生布局和安全区域机制。
